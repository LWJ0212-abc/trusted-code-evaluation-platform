# M0-B 业务数据库创建指南

## 1. 数据库边界

M0-B 使用独立的业务 MySQL，不复用 Keycloak 数据库。

| 数据库            | 宿主机端口 | 用途                                         |
| ----------------- | ---------: | -------------------------------------------- |
| `keycloak`      |   `3308` | Keycloak 用户、Realm、OIDC Client 和认证数据 |
| `code_platform` |   `3309` | 平台课程、提交、评测任务、Outbox、对象元数据 |

两套数据库可以使用同一个 MySQL 镜像，但必须使用不同的数据卷、数据库和账号。

## 2. 配置环境变量

在 `CodePlatForm/Server/.env` 中配置业务数据库：

```env
KEYCLOAK_DB_PORT=3308

TCEP_DB_HOST=127.0.0.1
TCEP_DB_PORT=3309
TCEP_DB_NAME=code_platform
TCEP_DB_USERNAME=coder
TCEP_DB_PASSWORD=coder_password
```

`TCEP_DB_PASSWORD` 只用于本地开发。真实环境必须使用随机生成的密码，并通过密钥管理系统注入。

## 3. 启动业务数据库

在 `CodePlatForm/Server` 目录执行：

```bash
sudo docker compose --env-file .env up -d business-mysql
sudo docker compose --env-file .env ps business-mysql
```

确认端口：

```bash
sudo docker port tcep-server-dependencies-business-mysql-1
```

预期包含：

```text
3306/tcp -> 127.0.0.1:3309
```

右侧 `3309` 是宿主机端口；容器内部使用 MySQL 默认监听端口，不对宿主机直接暴露 `3306`。

## 4. 手工创建数据库和账号

Compose 首次创建业务数据卷时会自动执行 `MYSQL_DATABASE`、`MYSQL_USER` 和 `MYSQL_PASSWORD`。如果要在已有 MySQL 实例中手工创建，使用 root 账号连接业务实例：

```bash
mysql -h 127.0.0.1 -P 3309 -u root -p
```

执行以下 SQL。密码请替换为 `.env` 中的实际值，不要把真实密码提交到 Git：

```sql
CREATE DATABASE IF NOT EXISTS `code_platform`
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER IF NOT EXISTS 'coder'@'%' IDENTIFIED BY 'coder_password';
ALTER USER 'coder'@'%' IDENTIFIED BY 'coder_password';
GRANT ALL PRIVILEGES ON `code_platform`.* TO 'coder'@'%';
FLUSH PRIVILEGES;
```

不要在 Keycloak 数据库连接上执行这段 SQL，也不要向 `keycloak` schema 创建业务表。

## 5. M0-B 表结构

连接业务数据库：

```bash
mysql -h 127.0.0.1 -P 3309 -u coder -p -D code_platform
```

执行以下建表 SQL：

```sql
USE `code_platform`;

CREATE TABLE IF NOT EXISTS source_object (
  upload_id CHAR(36) NOT NULL COMMENT '上传对象唯一标识',
  owner_id CHAR(36) NOT NULL COMMENT '对象所有者用户 ID',
  assignment_id CHAR(36) NOT NULL COMMENT '所属作业 ID',
  content_version CHAR(36) NOT NULL COMMENT '评测内容版本',
  object_bucket VARCHAR(128) NOT NULL COMMENT '对象存储桶',
  object_key VARCHAR(512) NOT NULL COMMENT '对象存储键',
  object_version VARCHAR(256) NULL COMMENT '对象存储版本',
  sha256 CHAR(64) NOT NULL COMMENT '对象 SHA-256 摘要',
  size_bytes BIGINT UNSIGNED NOT NULL COMMENT '对象字节数',
  validation_status VARCHAR(32) NOT NULL COMMENT '对象校验状态',
  expires_at DATETIME(6) NULL COMMENT '暂存对象过期时间',
  created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '创建时间',
  validated_at DATETIME(6) NULL COMMENT '校验通过时间',
  PRIMARY KEY (upload_id),
  UNIQUE KEY uk_source_object_location
    (object_bucket(64), object_key(255), object_version(64)),
  KEY idx_source_object_owner (owner_id, assignment_id),
  KEY idx_source_object_cleanup (validation_status, expires_at)
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS assignment_submission_counter (
  assignment_id CHAR(36) NOT NULL COMMENT '作业 ID',
  student_id CHAR(36) NOT NULL COMMENT '学生用户 ID',
  last_attempt_no BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '最近一次分配的提交序号',
  accepted_count INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '累计通过评测的提交次数，由评测结果处理逻辑更新',
  max_attempts INT UNSIGNED NULL COMMENT '最大提交次数；NULL 或 0 表示不限制',
  version BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '并发更新版本号',
  updated_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
    ON UPDATE CURRENT_TIMESTAMP(6) COMMENT '最后更新时间',
  PRIMARY KEY (assignment_id, student_id)
) ENGINE=InnoDB;

说明：`last_attempt_no` 由提交受理流程分配并递增；`accepted_count` 统计评测通过的提交，不在创建提交时递增。评测结果处理功能实现后，应在同一事务中完成结果幂等校验和计数更新，避免重复消费结果导致重复计数。

CREATE TABLE IF NOT EXISTS submission (
  submission_id CHAR(36) NOT NULL COMMENT '提交唯一标识',
  owner_id CHAR(36) NOT NULL COMMENT '提交者用户 ID',
  assignment_id CHAR(36) NOT NULL COMMENT '作业 ID',
  content_version CHAR(36) NOT NULL COMMENT '提交使用的内容版本',
  source_upload_id CHAR(36) NOT NULL COMMENT '已校验源码对象 ID',
  attempt_no BIGINT UNSIGNED NOT NULL COMMENT '用户在该作业中的提交序号',
  idempotency_key VARCHAR(128) NOT NULL COMMENT '客户端幂等键',
  source_sha256 CHAR(64) NOT NULL COMMENT '受理时源码摘要',
  source_size_bytes BIGINT UNSIGNED NOT NULL COMMENT '受理时源码大小，单位为字节',
  status VARCHAR(32) NOT NULL COMMENT '提交状态',
  submitted_at DATETIME(6) NOT NULL COMMENT '提交时间',
  created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '创建时间',
  updated_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
    ON UPDATE CURRENT_TIMESTAMP(6) COMMENT '最后更新时间',
  version BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
  PRIMARY KEY (submission_id),
  UNIQUE KEY uk_submission_idempotency
    (owner_id, assignment_id, idempotency_key),
  UNIQUE KEY uk_submission_attempt (assignment_id, owner_id, attempt_no),
  KEY idx_submission_assignment (assignment_id, owner_id, submitted_at),
  CONSTRAINT fk_submission_source
    FOREIGN KEY (source_upload_id) REFERENCES source_object (upload_id)
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS evaluation_task (
  evaluation_task_id CHAR(36) NOT NULL COMMENT '评测任务唯一标识',
  submission_id CHAR(36) NOT NULL COMMENT '关联提交 ID',
  assignment_id CHAR(36) NOT NULL COMMENT '作业 ID',
  student_id CHAR(36) NOT NULL COMMENT '学生用户 ID',
  content_version CHAR(36) NOT NULL COMMENT '评测内容版本',
  status VARCHAR(32) NOT NULL COMMENT '任务状态',
  revision BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '任务状态并发版本，也是事件 aggregate_revision 的来源',
  attempt_count INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '执行尝试次数',
  created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '创建时间',
  updated_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
    ON UPDATE CURRENT_TIMESTAMP(6) COMMENT '最后更新时间',
  PRIMARY KEY (evaluation_task_id),
  UNIQUE KEY uk_evaluation_task_submission (submission_id),
  KEY idx_evaluation_task_queue (status, created_at),
  CONSTRAINT fk_evaluation_task_submission
    FOREIGN KEY (submission_id) REFERENCES submission (submission_id)
) ENGINE=InnoDB;

说明：`evaluation.requested` 与 `result.accepted` 的 `aggregate_id` 都等于 `evaluation_task_id`，事件 `aggregate_revision` 对应该行的 `revision`。M0-B 的 `uk_evaluation_task_submission` 仅允许每次提交创建一个首评任务；人工重评启用前，需通过迁移调整此唯一约束并增加任务序号或等价区分字段，不能复用或覆盖旧 task。

CREATE TABLE IF NOT EXISTS outbox_event (
  event_id CHAR(36) NOT NULL COMMENT '事件唯一标识',
  event_type VARCHAR(128) NOT NULL COMMENT '事件类型',
  schema_version SMALLINT UNSIGNED NOT NULL COMMENT '事件结构版本，例如 1',
  aggregate_type VARCHAR(64) NOT NULL COMMENT '聚合类型，例如 EVALUATION_TASK',
  aggregate_id CHAR(36) NOT NULL COMMENT '聚合根 ID',
  aggregate_revision BIGINT UNSIGNED NOT NULL COMMENT '聚合版本',
  trace_id VARCHAR(128) NOT NULL COMMENT '请求追踪 ID',
  payload_json JSON NOT NULL COMMENT '事件 payload，不包含外层信封字段',
  occurred_at DATETIME(6) NOT NULL COMMENT '事件发生时间，按 UTC 存储',
  status VARCHAR(16) NOT NULL DEFAULT 'PENDING' COMMENT '投递状态：PENDING、PUBLISHING、PUBLISHED、DEAD',
  attempts INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '投递尝试次数',
  next_attempt_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '下次投递时间',
  claim_token CHAR(36) NULL COMMENT '投递器领取令牌',
  claimed_until DATETIME(6) NULL COMMENT '领取租约截止时间',
  last_error_code VARCHAR(128) NULL COMMENT '最近一次失败的安全错误码',
  created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '创建时间',
  published_at DATETIME(6) NULL COMMENT '收到 RabbitMQ Publisher Confirm 的时间',
  PRIMARY KEY (event_id),
  UNIQUE KEY uk_outbox_logical_event
    (aggregate_type, aggregate_id, event_type, aggregate_revision),
  KEY idx_outbox_pending (status, next_attempt_at),
  KEY idx_outbox_expired_claim (status, claimed_until)
) ENGINE=InnoDB COMMENT='事务性事件发件箱';

CREATE TABLE IF NOT EXISTS inbox_event (
  consumer_name VARCHAR(128) NOT NULL COMMENT '消费者名称',
  event_id CHAR(36) NOT NULL COMMENT '已消费事件 ID',
  event_type VARCHAR(128) NOT NULL COMMENT '事件类型',
  received_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '接收时间',
  PRIMARY KEY (consumer_name, event_id)
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS audit_event (
  audit_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '审计记录 ID',
  event_type VARCHAR(128) NOT NULL COMMENT '审计事件类型',
  actor_id CHAR(36) NULL COMMENT '操作者用户 ID',
  aggregate_id CHAR(36) NULL COMMENT '关联聚合 ID',
  trace_id VARCHAR(128) NULL COMMENT '请求追踪 ID',
  details_json JSON NULL COMMENT '审计详情 JSON',
  occurred_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '发生时间',
  PRIMARY KEY (audit_id),
  KEY idx_audit_aggregate (aggregate_id, occurred_at),
  KEY idx_audit_trace (trace_id)
) ENGINE=InnoDB;
```

## 6. M0 合成初始化数据

只使用 `fixtures/m0/seed.json` 中的用户、课程、作业和版本。计数器示例：

```sql
USE `code_platform`;

INSERT INTO assignment_submission_counter
  (assignment_id, student_id, last_attempt_no, accepted_count, max_attempts, version)
VALUES
  ('20000000-0000-4000-8000-000000000001',
   '00000000-0000-4000-8000-000000000001', 0, 0, 3, 0),
  ('20000000-0000-4000-8000-000000000001',
   '00000000-0000-4000-8000-000000000002', 0, 0, 3, 0)
ON DUPLICATE KEY UPDATE max_attempts = VALUES(max_attempts);
```

源码对象必须先通过对象存储校验，不能在这里伪造 `submission` 或 `evaluation_task`。

## 7. 验证数据库

```sql
SELECT DATABASE();
SHOW TABLES;

SELECT TABLE_SCHEMA, TABLE_NAME
FROM information_schema.TABLES
WHERE TABLE_SCHEMA IN ('keycloak', 'code_platform')
ORDER BY TABLE_SCHEMA, TABLE_NAME;

SHOW CREATE TABLE submission;
SHOW CREATE TABLE evaluation_task;
SHOW CREATE TABLE outbox_event;
```

预期结果：

- 当前数据库为 `code_platform`
- M0-B 七张表均存在
- `submission` 有 `uk_submission_idempotency`
- `evaluation_task` 有 `fk_evaluation_task_submission`
- `evaluation_task` 有 `revision`，新建任务初始值为 `0`
- Keycloak 的 `keycloak` schema 不出现业务表

## 8. 清理与重置

只删除本地业务数据卷：

```bash
sudo docker compose --env-file .env down
sudo docker volume rm tcep_business_mysql_data
```

这会永久删除业务数据库数据，但不会删除 Keycloak 数据卷 `tcep_keycloak_mysql_data`，也不会删除 RustFS 数据卷 `tcep_rustfs_data`。

不要在共享或生产环境执行上述命令。
